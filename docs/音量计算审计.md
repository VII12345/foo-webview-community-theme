# 音量计算审计

日期：2026-10-21
范围：本主题的**瞬时**与**平均**两条声压/音量计算链路，以及它们与 `foo_acoustic_stats`
插件那侧的对应关系。
结论先行：**没有发现会改变量级（1 dB 以上系统偏差）的错误**。发现三处口径差异与若干建模边界，
逐条列在第 6 节；按用户要求，本报告**不附带代码改动**。

---

## 1. 口径总表

| 量 | 单位 | 定义点 | 备注 |
|---|---|---|---|
| foobar 音量 | dB | 宿主 `get_volume` / 事件 | 0 = 满，−100 = 静音 |
| 音量条位置 | 0–100 | `volumeScale.ts` | 只是显示刻度，不改变发送给宿主的 dB |
| 数字电平 | dBFS | `rmsDbfsOfMeanSquare` | 满幅正弦 = 0 dBFS |
| 响度 | LUFS | `loudnessMeter.ts` | BS.1770 K 加权，Momentary 400 ms / Short-term 3 s |
| 耳放输出 | V rms | `ampVrmsAt0db × 10^((音量+增益)/20)` | `ampVrmsAt0db` 是 0 dBFS 时的输出 |
| 功率 | mW | `1000·V²/Z` | Z 为参考阻抗（Ω） |
| 声压 | dB SPL | `灵敏度(dB/V) + 20log10(V)` | 或 dB/mW 口径：`灵敏度 + 10log10(P)` |
| 平均声压 | dB SPL | `10log10(Σ能量/Σ秒)` | 能量的时间加权平均，不是 dB 的算术平均 |

## 2. 瞬时链路的逐环结论

### 2.1 音量刻度（`src/playback/volumeScale.ts`）——对

- 感知刻度 `dB = 50·log10(0.99p + 0.01)`：`p=0 → −100 dB`（静音），`p=1 → 0 dB`（满）。
  与 `positionOf` 互为反函数；`−100` 及以下与 `NaN` 都归到 0 位。
- 写回宿主走 `amplitudeOf`：`100·10^(dB/20)`，静音给 0。**只做一次换算**：读用宿主的
  `volumeDb`，写用 dB 再转幅度，不经过宿主报的百分比来回换，避免二次换算的舍入。
- 刻度只改条上的位置，不改 fb2k 音量——审计确认没有写 `setVolume` 的副作用路径。

### 2.2 数字电平（`rmsDbfsOfMeanSquare`）——对

`10·log10(2·均方)`。满幅正弦的均方是 0.5，×2 得 1 → 0 dBFS。若少乘这个 2 会低 3.01 dB，
这里的定标正确。

### 2.3 电压与声压（`soundPressure.ts` 频带路径）——对

```
v0    = ampVrmsAt0db · 10^((foobar音量 + 耳放增益)/20)
power = Σ_band v0² · rms² · share_b · 10^((频带响应_b + 加权_b)/10)
SPL   = 灵敏度(dB/V) + 10·log10(power)
```

- `share_b` 是频带功率占比（`liveBandPower.sharesOf` 按总功率归一，和为 1），所以
  `Σ share_b·10^(...)` 是以总电平为基准的加权平均，量纲正确。
- 频带响应与加权在 **dB 域相加后一次幂运算**，不是两步乘——正确（两者都是功率域的比值）。
- 灵敏度统一换算到 dB/V（`sensitivityDbPerVAtReference`）：dB/mW → dB/V 用
  `+10log10(1000/Z_ref)`，参考阻抗优先取测量档案 1 kHz 实测值，否则标称值。正确。
- 左右声道各算一遍，**取 SPL_A 最大的那个声道**出数（其余两种加权跟随该声道）。符合
  "单耳风险"的取法。
- 余量与超限**恒按 A 加权**（`margin = 80 − SPL_A`），与显示选哪种加权无关——已文档化。

### 2.4 两套回退路径——可用，但口径不同（见 6.1 / 6.2）

- **RMS 回退**（无频谱时）：平坦响应，`splA = splK = splZ = spl`。此时 `splA` 字段实际是
  Z 加权（未加权）值，但余量仍按它算。
- **LUFS 回退**（连 PCM RMS 都没有时）：`L_ch = LUFS + channelGainDb + volumeDb`，其中
  `channelGainDb = 10log10(2/Σw)` 把多声道换算到"立体声单声道"口径。定标推导见代码注释，
  与 EBU Tech 3341 的 1 kHz/−23 dBFS 用例一致。

### 2.5 加权曲线与频带积分（`splWeightingCurves.ts` / `splBands.ts`）——对

- A 加权用 IEC 61672 解析式，1 kHz 归一 +2.0 dB（解析式本身在 1 kHz 约 −2 dB），归一正确。
- K 加权复用 BS.1770 的双二阶级联，按实际采样率求系数，再以 1 kHz 归零。
- 31 段 1/3 倍频程 20 Hz–20 kHz；band 内取 8 个对数等距点做**功率平均**（dB 先换成功率再平均），
  对"带内响应不平"的情形是正确做法。

### 2.6 页面与插件的一致性——对（已实测）

两边是同一套算法、同一组常量：插件用 `double` 与 foobar 的最终输出流，页面用 `float32` 与
宿主推来的 PCM/频谱。同一段 −40.0243 dBFS 的 1 kHz 测试音上，插件读出
`SPL_A = 40.9556 dBA`；按上面的公式手算（v0 = 5.3033 V、−48 dB 设备音量、MDR-M1 灵敏度
114.477 dB/V）得 40.94 dBA，差值 0.01 dB 来自 1 kHz 处的频带响应与加权。**没有系统性偏差。**

## 3. 平均链路的逐环结论

### 3.1 采样条件（`loudnessStats.tick`）——对

只在"播放中 + DX52 自动读数生效 + 已选耳机 + 三种 SPL 均为有限值 + 读数新鲜（默认 5 分钟）"
时记一笔。任一不满足就跳过，不会把静音或过期读数算进平均。

### 3.2 时间记账——对（并保护了跳转）

- 同一曲目内位置增量合理（`0 < Δpos ≤ 2·Δwall + 1`）时用位置增量；否则取
  `min(2, Δwall)`。拖动进度条、循环重播、暂停都不会多记。
- 每拍最多 2 秒：页面被挂起后回来，那一拍不会把整段挂起时间补成收听。

### 3.3 能量积分与平均——对

```
每次：energy_A += 10^(SPL_A/10) · seconds
平均：10·log10(Σ energy / Σ seconds)
```

这是时间加权的**能量平均**，等价于"等效连续声级" $L_{eq}$，不是对每秒 dB 求算术平均
（后者会把响的段落低估）。三种加权各存一份能量，统计页跟随 SPL 加权设置。

### 3.4 双写与归属——对，有一个边界

页面与插件写同一份 `loudness-v2.json` 的约定是：**插件的 `stats.state` 存在时，页面不写文件**
（`pluginOwnsStats`）。审计确认：
- 插件在 `playback_stream_capture`（DSP 之后）采集，ReplayGain 只生效一次，插件不重复叠加；
- 页面侧的内存累计仍在跑，只是不落盘——若插件在运行中被卸载、`stats.state` 消失，页面会把
  自己那份（可能与插件不同步）写回去。属边界情况，见 6.3。

### 3.5 实测数据核对

- 半小时托盘测试：MDR-M1 桶从 6324.44 s 涨到 8065.58 s（**+1741.1 s ≈ 29.0 分钟**），
  能量 A 从 7.711315e9 涨到 9.708424e9，平均 `10log10(ΔE/Δt) = 60.60 dBA`。时间与能量
  同步增长，没有"时间涨了能量没涨"的错位。
- 测试音（−40.02 dBFS、设备 −48 dB）：单秒采样能量为 `10^(40.9556/10) ≈ 1.246e4`，
  与读数一致。

## 4. ReplayGain 只计一次——对

- 插件：`playback_stream_capture` 在 DSP 链之后，ReplayGain 已经体现在 PCM 里；插件不再读
  标签、也不额外乘增益。
- 页面：`fb.audio.subscribeStream` 拿到的是宿主播放链的输出流，同样已在 DSP 之后。
- 两处都没有"再叠一次 ReplayGain"的路径。

## 5. 单位与量纲检查——对

| 检查 | 结果 |
|---|---|
| dB ↔ 功率（×10 而非 ×20）在功率求和处 | 正确：`10^(dB/10)` |
| dB ↔ 幅度（×20）在电压处 | 正确：`10^(dB/20)` |
| mW ↔ W | 正确：`1000·V²/Z` 得 mW；显示层再换 W/µW |
| LUFS 定标（0 dBFS 正弦 ≈ 0 LUFS） | 正确：不额外 +0.691，也不 −2.32 |
| 夹取顺序 | `positionOf` 先判静音再夹；电压先判正再取对数；没有出现 `log10(0)` 的路径 |

## 6. 差异与边界（不影响量级，但值得知道）

### 6.1 RMS 回退把未加权值标成 A 加权

无频谱时 `estimateSoundPressureFromRms` 返回 `splA = splZ = 未加权值`。对低频内容，
真实 A 加权会比这个低若干 dB。此时 `marginDb` 也按这个值算，可能偏保守或偏乐观。
状态字段 `method: 'rms'` 已保留，界面若需要可以据此标注"近似"。

### 6.2 两条路径的参考阻抗口径不同

- 频带/RMS 路径：灵敏度按 `referenceImpedanceOhm`（优先实测 1 kHz）换算，功率显示也用它。
- LUFS 回退路径：dB/mW 换算用**标称** `headphone.impedanceOhm`。
阻抗随频率变化大的耳机上，两条回退路径可能差零点几 dB。影响很小，但在切换回退时可能看到
读数轻微跳变。

### 6.3 停滞时的时间上限不同

- 页面：每拍最多 2 秒。
- 插件：每行最多 300 秒（5 分钟）。

插件正常时每秒写一行，差值 ≈ 1 秒；只有进程被挂起（系统睡眠等）后才可能一次补记较多。
若对"睡眠期间不算收听"有严格要求，插件的 300 秒上限偏松。

### 6.4 页面内存在但未落盘的累计

插件接管写入后，页面的累计只在内存里；插件被卸载且其状态文件消失时，页面可能把自己那份
写回，覆盖插件后来累计的部分（时间窗口内的差异）。

### 6.5 估算模型本身的边界（非缺陷）

不建模：耳道耦合、头相关传输、耳机阻抗随频率变化（只用了参考阻抗 + 实测 FR 曲线）、
耳放输出阻抗的频率特性（DX52 只按 0.2 Ω 常数分压）。读数应理解为"基于实测 FR 的估算"，
不是校准过的声级计。

## 7. 结论

1. 两条链路的量纲、定标、对数域换算与能量平均均正确，未发现系统性偏差。
2. 与插件实现的一致性有真机数据佐证（同一测试音差 0.01 dB）。
3. 三处口径差异（6.1–6.3）属于"回退/异常路径"的精度问题，不是日常读数错误；按用户要求
   本次只记录，不修改代码。
4. 若后续要修，优先级建议：6.3（停滞补记上限）> 6.1（回退路径的加权标注）> 6.2（阻抗口径）。
